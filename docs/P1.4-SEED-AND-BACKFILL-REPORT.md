## 2. Master-Data Provenance & Sourcing Audit

To ensure master-data integrity and avoid asserting unverified assumptions as facts, every seeded entity was audited against verified project sources:

### 2.1 Root Institution (`institutions`)
* **Institution Code (`'CAMPUSONE'`):** Verified in `docs/PHASE0-DECISION-REGISTER.md` (Document ID `CAMPUSONE-DEC-REG-P0`, Policy 1: Single Institution).
* **Institution Name (`'CampusOne Institute of Technology'`):** Authoritative name specified in Phase 0 Decision Register and technical documentation.
* **Legal Name (`null`):** In `schema.prisma`, `legal_name` is an optional `TEXT` column. Earlier rehearsal scripts used an example value (`'CampusOne Education Trust'`), which has not been validated against an official statutory registration document. **Decision:** Explicitly seeded as `null` pending formal trust/society charter review.
* **Website (`null`):** In `schema.prisma`, `website` is optional. The domain `https://campusone.edu` is provisional (derived from admin email format). **Decision:** Explicitly seeded as `null` pending official domain registration signoff.
* **Status:** `'active'`.

### 2.2 Main Campus (`campuses`)
* **Campus Code (`'MAIN'`):** Directly sourced from `docs/PHASE0-DECISION-REGISTER.md` (Policy 1: Single Institution with Multi-Campus Hierarchy).
* **Campus Name (`'Main Campus'`):** Authoritative campus designation.
* **Timezone (`'Asia/Kolkata'`):** Standard Indian Standard Time (IST) per operational requirements.
* **Address (`null`):** Left `null` (not invented).

### 2.3 Academic Programs (`programs`)
* **Program Code (`'BTECH-CS'`):** Deterministically normalized from legacy `Student.degree` (`'B.Tech'`) and legacy `Department.code` (`'CS101'`).
* **Program Name (`'Bachelor of Technology in Computer Science'`):** Derived standard degree nomenclature.
* **Department Name (`'Computer Science'`):** Cleaned from legacy `Department.name` (`'Computer  Science'` with duplicate whitespace collapsed).
* **Provenance Note:** While `BTECH-CS` is the deterministic system code derived from legacy records, official program code endorsement by the Board of Studies / Academic Council is pending.

### 2.4 Rooms (`rooms`)
* **Room Number (`'501'`):** Directly sourced from legacy `TimetableEntry.roomNumber`.
* **Campus Link:** Associated with campus `'MAIN'` per the single-campus operational topology established in Policy 1.

## 4. Quarantined Legacy Records (Privacy Preserved)

During the scan of the legacy `Student` table, one record failed to match the approved cohort mappings:

* **Reference Alias:** `UNRESOLVED_STUDENT_01`
* **Degree:** `B.Tech` | **Semester:** `1` | **Batch Value:** `"2026-2026"`
* **Quarantine Rationale:** The Phase 0 Decision Register (`docs/PHASE0-DECISION-REGISTER.md`, Part A, Section 3) approved historical cohort mappings exclusively for the active cohort: Batch `2023-2027` (Semesters 1 through 7). The string `"2026-2026"` is anomalous (non-standard single-year cohort string). Rather than guessing or silently coercing this student to an arbitrary term, the seed script documented this as an **UNRESOLVED HISTORICAL COHORT** and quarantined the mapping.
* **Impact Isolation:** This student's mapping quarantine does **not** block or invalidate any unrelated, verified master records.
* **Academic Decision Required:** Academic administration must confirm whether `UNRESOLVED_STUDENT_01` represents the newly admitted 2026–2030 cohort (entering Semester 1 in `2026-ODD`) or a single-year special curriculum.

## 5. Deterministic Legacy ID Mapping (`_id_map`) Specification

To guarantee stability, repeatability, and permanent traceability across all environments and runs, the `_id_map` initialization follows a strict cryptographic specification:

1. **RFC 4122 Version 5 Specification:** Uses SHA-1 hashing over a fixed namespace and UTF-8 formatted name string.
2. **Fixed Project Namespace:** Standard DNS UUID `6ba7b810-9dad-11d1-80b4-00c04fd430c8`.
3. **Exact Name Format:** `${tableName}:${oldId}` (exact casing, colon delimiter, exact legacy string ID).
4. **Preservation Rule:** `SELECT new_id FROM _id_map WHERE table_name = $1 AND old_id = $2` is executed before inserting. Any existing mapping is permanently preserved without re-hashing or modification.
5. **Bidirectional Uniqueness:**
   * `(table_name, old_id)` PRIMARY KEY prevents duplicate source mappings.
   * `(table_name, new_id)` UNIQUE constraint prevents destination UUID collisions.
